# Guide: modelling a part from a drawing

Method proven on 55 parts generated by script in a live CATIA V5 R19. It is written for an AI agent
(or a person) who fills `templates/part_template.py`; every rule below is either enforced by the
`PartScript` DSL or checked after the run.

```python
from catia_mcp.scripting import PartScript, cli
p = PartScript("Flange", "out/Flange")          # result body = "Flange_Resultat"
with p.sketch("xy", "Sk_Disc") as sk:
    sk.circle(0, 0, 40)
p.pad("Disc_D80_T10", 10)
p.save()
p.checks(volume=3.14159 * 40**2 * 10, bbox=(80, 80, 10))
```

## 1. Workflow

1. **Read the drawing** (scale in the title block, every view). A dimension that is not written is
   MEASURED on the drawing, never guessed. Cross-check top, front and section views before modelling.
   With vector PDFs the `drawing_*` tools give exact circles, arcs and lines in part millimetres.
2. **Choose the frame** and write it in the script docstring: origin on a main axis or a symmetry
   plane, revolution axis on a frame axis, so the drawing views map onto sketch planes.
3. **Plan the bodies**: base shape, then one body per functional zone (boss, pocket, holes...).
4. **Compute by hand** the final volume and the overall size. Put them in `p.checks(...)`.
5. Fill the template, then `python my_part.py --dry-run`: every step is validated against the real tool
   schemas without touching CATIA.
6. Run it (`python my_part.py`). Read the log: `SUMMARY: N OK, 0 ERR`, `CHECKS: all passed`.
7. **Look at the result** (screenshots, and the profile drawn over the drawing for any non-trivial
   sketch). A plausible volume does not prove the shape.

## 2. Frame and sketch planes

| Plane | Sketch H axis | Sketch V axis | Pad "normal" direction |
|---|---|---|---|
| `xy` | X | Y | +Z |
| `yz` | Y | Z | +X |
| `zx` | Z | X | +Y |

- `p.plane("xy", offset=25)` = a plane parallel to `xy`, 25 mm along its normal (signed).
- `p.plane(face_point=(x, y, z))` = the planar face of the ACTIVE body containing that point (strictly
  inside the face, not on a border). A sketch on a face of ANOTHER body cannot be solved by CATIA:
  use an offset plane instead.
- All values are millimetres and degrees. The DSL refuses text, NaN, and anything beyond 100 000 (a
  metre or micrometre mix-up).

## 3. Multi-body method

- `<Part>_Resultat` is the final body (`PartScript` renames the main body for you, in any UI language).
  Put the base shape in it.
- Each functional zone gets its own body: `p.body("Body_Boss")` creates and activates it. Model the
  zone as SOLID material in that body, then merge it:
  `p.combine(p.result, "Body_Boss", "assemble", "Add_Boss")`.
- Material to remove is modelled as a solid cutter in its own body and merged with `"remove"`
  (`p.combine(p.result, "Body_Bore", "remove", "Remove_Bore_D30")`). Make cutters LONGER than the part
  (a symmetric pad through the origin plane): a cutter that ends exactly on a face leaves a skin.
- A body that is never merged is refused at `save()` (`allow_unmerged=True` if intentional).
- A very simple part (a rod, a nut) still gets two logical bodies when that makes sense (base +
  machining); do not invent absurd ones.
- After `combine`, the DSL re-activates the target body: work continues there.
- A body merged into another disappears from `Part.Bodies` (reach it through its feature).

## 4. Naming (every object, no exception)

| Object | Pattern | Example |
|---|---|---|
| Result body | `<Part>_Resultat` | `Flange_Resultat` |
| Other bodies | `Body_<zone>` | `Body_Bolt_Holes` |
| Sketches | `Sk_<role>` (+ dimension) | `Sk_Disc`, `Sk_Slot_W8` |
| Features | `<Role>_<key dimension>` | `Bore_D30`, `Chamfer_2x45`, `Hub_D44_H12` |
| Booleans | `Add_<x>` / `Remove_<x>` | `Remove_Bore_D30` |

The DSL refuses an empty name, `Pad.1`, `Sketch.3`, `PartBody`, a bare type (`pad`, `Hole_1`), spaces and
accents, and a name already used in the script. `catia_get_tree` ends with an `AUDIT:` line; the run fails
unless it says `AUDIT: OK`. A name like `Esq_R57.5` (a decimal dimension) is fine; CATIA's own defaults
always end with `.<counter>`.

## 5. Order of features

1. Base shape (pad or shaft) in the result body.
2. Zones added, each in its body, merged with `assemble`/`add`.
3. Cutters (bores, slots, holes), merged with `remove`.
4. Patterns of features that already exist (`pattern("circ", ...)`, `pattern("rect", ...)`).
5. Fillets and chamfers LAST (they need finished edges), `mirror` when the part is symmetric.

One sketch feeds exactly one feature. A sketch is closed automatically by the next feature. Pads and
pockets can use `sketch=` to name a specific earlier sketch.

## 6. Sketch rules

- Closed profiles only for pad/pocket/shaft/groove. `poly(points)` closes itself; `profile(start, segments)`
  mixes `line_seg(to)` and `arc_seg(to, center, "ccw"|"cw")`.
- `circle` takes a RADIUS, `hole` a DIAMETER (the parameter names say it).
- The DSL refuses: a self-crossing outline, a zero-area outline, a zero-length line, an arc whose two end
  points are not at the same distance from its center (more than 0.001 mm apart).
- An arc sweeping more than 180 degrees is allowed but logged in `p.warnings`: it is the classic sign of an
  inverted direction. A VALID outline can still be WRONG (a bulb of R19.5 was kept in a slot because one arc
  was drawn `ccw` instead of `cw`: CATIA accepted it, the volume looked plausible). Compare the outline with
  the drawing view.
- Separately drawn lines and arcs only join within about 0.0001 mm; `profile` builds real connected contours.
- Symmetric pad: `height` is the TOTAL length (half each side). `second_height` gives an independent length
  on the other side; do not combine it with `symmetric`.

## 7. Revolved parts

```python
with p.sketch("xy", "Sk_Half_Profile") as sk:            # H = X, V = Y: axis of revolution = X axis
    sk.poly([(0, 0), (0, 12), (30, 12), (30, 8), (50, 8), (50, 0)])
p.shaft("Turned_Body", "h")                               # "h": revolve about V=0, "v": about H=0
```

- Draw a HALF profile on ONE side of the axis. The DSL refuses a profile that spans both sides.
- `axis="sketch_line"` uses a line drawn with `sk.line(..., axis=True)` (exactly one).
- `groove` is the cut version. An axis line marked as construction geometry does not work.

## 8. Designating geometry by points

Faces and edges are designated by a 3D point in part millimetres, never by index.

- `hole(name, point, diameter, depth=... | up_to_point=...)`: `point` lies ON the entry face.
- `fillet(name, radius, [(x, y, z)])` / `chamfer(...)`: one point ON each edge.
- `plane(face_point=...)`, `mirror(plane_face_point=...)`, `pattern("circ", axis_face_point=...)`: a point
  strictly INSIDE the face (or on the cylinder), never on its border, or two faces are at distance 0.
- To find points: `catia_list_edges` / `catia_list_faces`. Cost is about 50 ms per candidate face or edge on the
  CATIA side, so on a dense part (grooved tyre, 900 edges = 45 s and minutes at 100 % CPU) aim at one
  point and never list the whole part. A tolerance of 0.01 mm is too much for a point that must lie on a face.
- Patterns copy the SHAPE the original feature cut, not its limit rule. A radial hole that only went 1.7 mm
  deep (a "through" cut stopping at a groove bottom) produced 7 blind copies. Give the original a fixed depth.
- Threads: `catia_thread` (cosmetic) on the cylindrical face; the cylinder keeps its nominal diameter.

## 9. Built-in controls

| Control | How | Fails when |
|---|---|---|
| Volume change of every solid feature | Automatic (`[check] volume change` in each result) | 0 (feature did nothing), wrong sign (a pocket that adds), or differs from `expect_dvol=` |
| Final volume, mass | `p.checks(volume=..., mass=...)`, relative `tol=0.02` | measured value differs |
| Overall size | `p.checks(bbox=(dx, dy, dz))`, `bbox_tol=0.5` mm | one axis differs (`None` skips an axis) |
| Naming audit | Automatic (`catia_get_tree`) | any default name left |
| Steps that did not run | Automatic | the run stopped early: checks are not evaluated |

- Volume change is signed: a pad adds, a pocket/groove/hole removes. Exception: in a body that holds no
  material yet (only cutters), a "removal" shows up as added volume: the DSL does not check the sign there.
- `expect_dvol=` gives an exact expectation for one feature: a disc pad of R10 x 10 is `3141.6`.
- Pad/pocket with a computed value: `π r² h`, `w * d * h`. Do this arithmetic BEFORE running.
- The run stops at the first failed step; `--keep-going` continues (the state of the document is then
  uncertain: a failed feature stays in the tree and makes later updates fail. `catia_delete_feature` repairs it).

## 10. Pitfalls with numbers

| Symptom | Cause | Rule |
|---|---|---|
| 300 mm obtained for a symmetric pad of 150 | CATIA's `IsSymmetric` puts the length on EACH side | `height` = total; the tool halves it |
| 7 blind holes instead of 8 through | pattern copies the cut shape (1.7 mm) not "up to last" | fixed depth on the original |
| Plausible volume, wrong shape | one arc drawn the long way round | look at the outline vs the drawing; heed `[check]` for arcs over 180 degrees |
| Sketch on a face of another body never solves and can crash CATIA on close | unsupported by CATIA | offset plane in the active body |
| Feature fails and every later `Update` fails | failed feature stays in the tree | delete it, then continue |
| Sketch stays beside its feature in the tree | sketch not the work object when the feature is created | done by the tool for the last sketch: keep one sketch per feature |
| Edge fillet refused even at R10 | convex edge at 120 degrees between an arc and a plane | check the edge geometry before insisting |
| Body cannot be found after `assemble` | absorbed body leaves `Part.Bodies` | address it through its feature |
| Active body forgotten after reconnecting | server-side cache lost | `p.activate(body)` |
| A step "hangs" for minutes | listing faces/edges on a dense part, or a modal dialog | the runner kills CATIA after `--hang-seconds` (default 600); popups with a single OK button are closed by the watchdog |

## 11. Before saying "done"

- Log: `SUMMARY: N OK, 0 ERR`, `CHECKS: all passed`.
- Profiles compared with the drawing (overlay), screenshots compared with the drawing's isometric view:
  same shapes, nothing extra, nothing missing.
- Interpretation choices written down (ambiguous dimension, chosen reading).
- For assembly work, note the part's interfaces: axes (point + direction), bearing faces (position), bores,
  in part coordinates. They become the constraint points of `AssemblyScript` (see `GUIDE_ASSEMBLY.md`).
